# Composition-control figure data

The tidy tables the three control panels read. Each generator reads one or two of these and nothing
else, so a fresh clone can render them with no downloads and no GPU:

```bash
bash analyses/controls/run_composition_controls.sh --figures
```

`scripts/build_figure_data.py --experiments controls` writes this directory from a completed
`--run`. It is the only step that reads the dated run directories under `results/`, so those stay
local build artifacts and these tables are the tracked form of the numbers. Every table is
validated (columns, uniqueness, full 32-block coverage, expected category counts) and staged in a
temporary directory, then moved into place only once all of it passes.

## Grain

`control_preservation` merges the within-family and between-family control scores into one long
table. `family` is set on within-family rows and empty on between-family rows, whose geometry is a
single family x family matrix per block. Panel 04 plots the mean over families; panel 12 uses the
per-family values.

The two identity tables are sequence-level, not geometry: `control_identity` is one row per rung and
`control_identity_by_family` splits the same measurement per family, so the within-rung test
compares families inside one rung rather than comparing rungs to each other.

## Not here

The control sequences themselves, the Evo2 embedding caches and the per-block score tables are not
tracked. They are rebuilt by `--run`.
